# Plan 4.1: Likes & Comments Backend + DB Schema

## Objective
Create the Likes and Comments database tables and implement the corresponding CRUD API endpoints.

## Context
- .gsd/SPEC.md
- init_db.js
- routes.js
- db_setup.sql

## Tasks

<task type="auto">
  <name>Create Likes and Comments Tables</name>
  <files>init_db.js, db_setup.sql</files>
  <action>
    - Add a `Likes` table: like_id (PK), user_id (FK→Users), meme_id (FK→Memes), created_at. Add UNIQUE constraint on (user_id, meme_id) to prevent duplicate likes.
    - Add a `Comments` table: comment_id (PK), user_id (FK→Users), meme_id (FK→Memes), content (CLOB), created_at.
    - Add corresponding sequences and triggers in init_db.js.
    - Document the DDL in db_setup.sql.
  </action>
  <verify>grep -q "Likes" init_db.js && grep -q "Comments" init_db.js</verify>
  <done>Likes and Comments tables exist in the schema with proper constraints.</done>
</task>

<task type="auto">
  <name>Implement Likes and Comments API Endpoints</name>
  <files>routes.js</files>
  <action>
    - POST /api/memes/:id/like — Toggle like (like if not liked, unlike if already liked). Protected.
    - GET /api/memes/:id/likes — Get like count and whether current user liked it.
    - POST /api/memes/:id/comments — Add a flat comment. Protected.
    - GET /api/memes/:id/comments — Get all comments for a meme with author names.
    - Update GET /memes to include like count per meme.
  </action>
  <verify>grep -q "comments" routes.js && grep -q "like" routes.js</verify>
  <done>Like toggle, comment creation, and retrieval endpoints work correctly.</done>
</task>

## Success Criteria
- [ ] Likes and Comments tables created with proper FK/unique constraints.
- [ ] Like toggle, comment add, and list endpoints are functional.
